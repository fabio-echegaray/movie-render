1. CRITICAL BUGS
────────────────

  [OPEN]  1. `parallel | True` always forces parallel (`_render_movie.py:37`)
               — `|` is bitwise OR (`True | False` = 1), so every movie
               renders in parallel mode regardless of the flag. Comment says
               "remove True value set for debugging". This is the gate that
               forces all renders into the broken parallel path.
               Fix: change `parallel | True` to just `parallel`.

   [OPEN] 53. FrameNotFoundError silently swallowed (`_sequential.py:166-167`)
               — `except FrameNotFoundError: continue` — no log message,
               no warning. Missing frames are silently omitted from output.
               Fix: log a warning before continuing.

   [OPEN] 54. Temp directory not cleaned up on exception (`_sequential.py:207`)
               — `shutil.rmtree(self._tmp)` not in `try/finally` block.
               If `write_videofile()` raises, the temp dir is orphaned.
               Fix: wrap cleanup in `try/finally`.


2. CODE QUALITY — DUPLICATION & ARCHITECTURE
────────────────────────────────────────────

   [OPEN]  12b. ConfigMovie/ConfigPanel should be dataclasses, not NamedTuples
               — 23+ fields, immutable, no defaults, no validation. A
               `@dataclass` with `field(default=...)` and `__post_init__`
               validation would eliminate defensive code in header readers.

   [OPEN] 55. Missing re-exports in overlays/__init__.py and plugins/__init__.py
               — `Arrow`, `ArrowOverlayPlugin`, `Position` defined but not
               exported from `movierender.overlays`.
               — `movierender.plugins/__init__.py` is completely empty.
               Fix: add explicit re-exports.

   [OPEN] 56. Variable `id` shadows built-in (`_arrow.py:16`, `plugins/overlay.py:14`)
               — Parameters named `id` shadow the built-in `id()` function.
               Fix: rename to `identifier` or `overlay_id`.


3. PERFORMANCE
──────────────

  [OPEN] 29. MovieRender saves every frame to disk then re-reads it
              (`_sequential.py:260,130`) — the frame data is already a numpy
              array; capturing it in memory would eliminate the I/O round-trip.
              Fix: compare `frame_count × frame_bytes` against available
              system memory. If it fits, keep rendered frames in a list and
              feed them directly to moviepy. Otherwise, fall back to the
              current disk path. Available memory can be read via
              `psutil.virtual_memory().available` or `os.sysconf`.


4. UX
──────

   [DONE] 47. Graceful early termination in `render_folder_cmd` (`_render_folder.py:34`)
                — When rendering a folder of config files, the user should be
                able to press Ctrl-C once to finish the current movie and stop
                (no further movies), or press Ctrl-C twice to terminate
                immediately. Currently, any KeyboardInterrupt kills the entire
                batch mid-render.
                Fix: two-phase SIGINT handler in `_render_folder.py`:
                first Ctrl-C sets `fileops.__STOP_REQUESTED` and replaces
                handler; current render finishes normally, folder loop checks
                `__STOP_REQUESTED` after each render and breaks. Second Ctrl-C
                sets `fileops.__THREAD_STOP_REQUESTED` (tells z-projection
                background thread to stop) and raises `KeyboardInterrupt` for
                immediate termination. `_base_composer.py` no longer catches
                KeyboardInterrupt in the sequential path (unnecessary — first
                press doesn't raise one, second press propagates through).

   [DONE] 47b. Z-projection hang on Ctrl-C (`_base_composer.py:212`)
                — First implementation of point 47 caused z-projection
                background threads to hang the system. Pressing Ctrl-C stopped
                all z-projection threads mid-computation, leaving the main
                render loop waiting for images that would never arrive.
                Fix: two-event approach — `__STOP_REQUESTED` for the folder
                loop (first Ctrl-C), `__THREAD_STOP_REQUESTED` for background
                threads (second Ctrl-C / SIGTERM). Background thread checks
                `__THREAD_STOP_REQUESTED` and exits when set.
                FileOps: removed SystemExit from _zproject() except clause
                so second Ctrl-C terminates threads immediately.
                FileOps: `__IS_EXITING` renamed to `__THREAD_STOP_REQUESTED`.

5. CROSS-PROJECT
────────────────

   [DONE] 48. Check and align dependencies between FileOps and MovieRender
               — MovieRender depended on imageio, roifile, tifffile, and
               typing_extensions without listing them (relied on transitive
               installs). Added all four explicitly.
               — numpy spec tightened to `>=1.24,<2.0.0` to match FileOps
               upper bound (numpy 2.x would break FileOps).
               — FileOps pandas spec bumped from `>=1.2` to `>=2` to match
               MovieRender requirement (projects are always co-installed).

   [DONE] 49. Upgrade numpy to >=2.0.0 across both projects
               — numpy 1.x is EOL; 2.x brings performance improvements and
               new APIs. Breaking changes to fix:
                 * np.isscalar → np.ndim(obj) == 0  (overlay.py:38)
                 * np.isreal  → np.isrealobj        (_z_array.py:56,
                                                     _time_array.py:46)
                 * np.NaN     → np.nan              (_mmanager_metadata.py:94,103)
               — Both pyproject.toml files updated from `>=1.24,<2.0.0` to
                 `>=2.0.0` (upper bound removed).

   [OPEN] 50. Add classifiers for Python 3.12, 3.13, 3.14 to pyproject.toml
               — Keep existing `requires-python = ">=3.9"` and classifiers
               for 3.9, 3.10, 3.11; add 3.12, 3.13, and 3.14 so the full
               range of supported versions is declared.

   [OPEN] 51. Project-folder-level configuration with section-level overrides
               — Add the ability to place a project-level config file (e.g.
               in the root folder passed to `render_folder`) that sets
               default rendering options (rescale, gamma, colors, etc.).
               — Individual configuration file sections can override these
               defaults, and section-level parameters take highest priority.
               — This avoids repeating the same options across many config
               files in the same project folder.

   [OPEN] 52. Render commands access media files excessively before rendering
               — Before a render starts, the same media files are opened,
               read, and/or queried multiple times. This causes significant
               startup delay (especially over network mounts).
               — Root cause is likely in FileOps
               (image loading, metadata parsing, file discovery).
               — Needs profiling to identify redundant accesses, then
               split fixes across MovieRender (call patterns) and
               FileOps (caching, lazy loading).
