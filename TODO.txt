1. CRITICAL BUGS
────────────────

  [OPEN]  1. `parallel | True` always forces parallel (`_render_movie.py:37`)
              — `|` is bitwise OR, not logical. Every movie renders in
              parallel mode regardless of the flag. Should be
              `parallel=parallel`.


4. CODE QUALITY — DUPLICATION & ARCHITECTURE
────────────────────────────────────────────

  [OPEN]  12b. ConfigMovie/ConfigPanel should be dataclasses, not NamedTuples
              — 23+ fields, immutable, no defaults, no validation. A
              `@dataclass` with `field(default=...)` and `__post_init__`
              validation would eliminate defensive code in header readers.

  [OPEN]  13b. Plugin naming convention is fragile and undocumented — FileOps
              matches config types to readers by string-concatenating
              `_header_reader` (`config.py:113`). A misnamed plugin silently
              does nothing. Should be an explicit mapping or registry.


6. DEPENDENCIES
───────────────

  [OPEN] 25. Both projects lack optional dependency groups — FileOps forces
              `vtk`, `pycromanager`, `matplotlib` etc. for basic TIFF loading.


7. TESTING
──────────

  [OPEN] 27. FileOps has essentially no unit tests (4 tests with hardcoded
              absolute paths). MovieRender now has 87 unit tests across
              5 test files covering overlay utils, rescale, pipelines,
              channel config, and secs_to_string.

  [OPEN] 28. `unittest.TestCase` instead of pytest — both projects should
              modernize to pytest with plain assertions and fixtures.


8. PERFORMANCE
──────────────

  [OPEN] 29. MovieRender saves every frame to disk then re-reads it
              (`_sequential.py:260,130`) — the frame data is already a numpy
              array; capturing it in memory would eliminate the I/O round-trip.

  [OPEN] 30. FileOps re-reads config files multiple times (`config.py:295,322`)
              — `build_config_list` parses the same file twice.

  [OPEN] 31. Z-projection busy-wait polling (FileOps
              `_shared_zproj_state_mixin.py:160-176`) — `time.sleep(2)` loop
              instead of `threading.Event`.
